# 每一步接收什么、生成什么

## 第一阶段：选高光时间

输入是原视频和画幅索引。Video-ORA-4B按32秒窗口、24秒步长发现事件；主体问答帮助确定事件对象；程序去重后由ORA复看视频筛选事件；最后进行时间定位。`uncertain`事件也进入后续定位，流程不强制凑固定覆盖比例。

原生定位格式不合法的事件，会使用模型官方时间定位提示再尝试一次；仍失败时保留自动发现区间。失败回退在记录和报告里明确标记，不能把它当作成功精确定位。

程序通过FFprobe读取原视频逐帧PTS，将模型秒数映射为原帧号。高光段内每一帧都会输出，支持可变帧率视频。`grounded`作为默认时间交接，`recall`是备用导出，两者都保留完整视频列表。

## 第二阶段：生成裁剪窗口

输入推荐使用 `temporal_handoff.jsonl`。它同时含高光帧区间、主体和动作说明。第二阶段冻结高光帧集合，只处理画面的裁剪位置。

1. 按源尺寸和目标比例生成最大的合法中心框，作为基础框和失败回退。
2. YOLO11m每3个高光帧检测一次主体，再插值和平滑，补齐逐帧位置。
3. YOLO11m-pose只处理自动主体提示为人物的16:9视频，根据脸和肩膀调整上下构图。
4. BoT-SORT每个连续高光段重置轨迹，使用同一检测模型的原生特征锁定主体。当前主要修正横向位置。
5. 检查视频ID、画幅、帧集合、整数坐标、正宽度和画面边界，打包最终JSONL。

YOLO识别的人或动物小框是定位依据；最后交的 `[x,y,w]` 是整个裁剪窗口。

## 时间和空间分开验收

时间交接可以直接给其他空间程序使用。已有交接文件时，`spatial --handoff ...` 不会重新运行ORA。空间程序不得通过删除、补选或移动时间段来改善自己的结果。

四条空预测等情况应原样保留为空。没有主体检测时使用自动回退，不进行人工修改。

## 断点继续

同一配置和输入再次运行时，时间阶段复用有效记录与回答缓存；空间阶段复用按视频保存的关键帧检测和跟踪缓存。输入、代码、索引或权重指纹不一致时拒绝复用。

正式输出存在时程序停止，防止覆盖。新实验优先修改 `run_root` 为新目录。中间阶段受资源限制失败后，先检查日志和资源，再恢复；不要把只有中心框的准备文件当成正式结果。
