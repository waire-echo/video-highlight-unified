## 判断

审查的主判断成立：故障主要在批处理工程链路，不能把“一个窗口/worker 出错”当成
“整批都无效”。但它审的是旧提交，不能把其中旧计数/旧路径的描述当作当前已改代码的状态。
正常模型、Adapter、Prompt 和显式采样参数不自动更换；异常恢复独立记录。
所有兜底只保证可审计与协议合法，不代表时间定位/主体选择正确，更不代表分数提高。

时间越界不是把 0.5 改成 5。intersection 策略对 `[-5,8)`、`[27,37)` 分别取

## 没有照单全收 / 仍须验收

1. **不启用未经验证的 OOM 自动减帧/换视觉预算。** 这会改变模型看到的内容，
   外层参数改了还不等于配置可用。现在有限重试采用同一冻结配置；低资源 profile 必须另做 GPU 容量与正常样本回归后才能启用。
2. **没有虚构整场比赛时限。** 配置提供窗口、空间视频和阶段命令预算；初值需按赛方时限和目标卡实测调整，阶段总预算用尽会保存检查点并停止，不伪装成功。
3. **不宣称与旧 41.09 包逐帧相同。** 修复 PTS 帧映射会改变旧错误公式的结果；新包移除了按旧测试视频哈希选择的检测参数。正常有效框的保留在 CPU 测试中检查，但新包真实 GPU 算法等价/质量回归尚未完成。
4. **不猜无法确认的原坐标。** 当前输入要求可解码、严格递增 PTS；非零旋转元数据明确拒绝，待补原坐标映射验证。缺模型、无 GPU、错误资产/输入身份、磁盘满等全局故障仍会失败。
5. **没有以 CPU 模型替身冒充 GPU 验收。** 当前测试覆盖真实短视频/FFmpeg、合并、PTS、严格协议校验、ZIP、移动目录及真实子进程崩溃/超时；神经网络调用是替身。基础模型大包、干净 Python 3.11/CUDA 环境安装、断网加载、两卡真实推理及最终定位得分仍待实测。
6. **解析修改不会无条件复用旧回答。** 整体代码指纹改变默认产生新 run；保留显式严格快照导入给人工核对来源使用，不自动把任意旧 run 当成本次实验结果。
