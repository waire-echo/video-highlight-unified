# 视频高光两阶段工作台与 TUI 计划

> 历史计划：统一状态机、版本清单、TUI/WebUI、输入准备、续跑、日志和正式产物下载已经实现；GPU 新推理验收、三路同步对比和预计剩余时间仍待完成。当前状态以根目录 [功能索引](../../docs/feature_index.md) 和 [README](../../README.md) 为准。下面保留原计划，不把其中的计划名称当作实际 CLI/版本 ID。

基准：`ora-spatial-scene-general-v3-20261010`
计划日期：2026-10-11（Asia/Hong_Kong）

## 1. 目标

在当前已验证的流程上增加一个统一工作台，让队员可以完成以下操作：

- 只跑前半阶段：从原视频选择高光时间段；
- 只跑后半阶段：读取已有时间结果，生成逐帧空间裁剪框；
- 连续跑完整两阶段，并明确展示中间交接；
- 选择原视频、模型、配置、最终输出和中间产物目录；
- 查看逐视频进度、GPU/CPU/内存、日志、断点和预计剩余时间；
- 查看失败视频、失败阶段、异常原因及可复用的已完成缓存；
- 自动识别已有输入、历史结果和运行目录；
- 生成原画、基准结果和新结果的三路同步对比视频；
- 从 README 快速找到已有功能，避免再次实现相同工具。

TUI 只负责组织和展示。时间选择、空间定位、裁剪、校验和渲染继续调用仓库中的公共实现，不能在 TUI 内复制一份算法。

## 2. 不可破坏的基准

### 2.1 保留兼容模式

新增永久入口：

```text
compat/scene-general-v3-20261010
```

兼容模式固定：

- 基准源码和 Prompt 哈希；
- Video-ORA-4B revision 与权重分片哈希；
- 模型请求参数；
- 输入视频和基础预测哈希；
- 抽样、候选、平滑与导出参数；
- vLLM 关键启动参数；
- 原视频帧号与时间戳契约。

README、TUI、日志和界面升级可以继续进行，但兼容模式的模型请求 payload、请求顺序和最终 JSONL 不允许悄悄变化。

### 2.2 禁止隐藏处理

以下行为不得作为“顺手优化”隐藏在流程中：

- 改原视频 FPS；
- 隐式丢帧、补帧、重复帧或改变原始帧号；
- 把秒数按固定 FPS 粗略换算，忽略原始 PTS；
- 未登记的缩放、裁边、旋转、色彩转换或重新编码；
- 自动改变高光片段长度、阈值、Prompt 或候选数量；
- 针对单个测试视频写特殊规则；
- AI 在运行时修改代码或人工修正单条比赛结果；
- 把测试视频发送到外部 API。

模型推理需要的图像缩放与最终成片缩放是两类操作。前者只能影响模型输入图像，不得改变输出对应的原视频帧号；后者必须写入渲染配置和产物清单。

### 2.3 每次运行先生成执行计划

按下“开始”前，TUI 必须展示并保存 `plan.json`：

```text
输入视频/目录及数量
前半阶段 pipeline、模型、Prompt、配置
前后阶段交接文件与转换步骤
后半阶段 pipeline、模型、Prompt、配置
最终输出目录
中间产物目录
是否生成预览或三路对比
是否处理音频
渲染分辨率、时间基准和 FPS 策略
资源与并发策略
将运行的完整命令
```

“自动”设置也必须在 `plan.json` 中展开成实际值，不能只记录 `auto`。

## 3. 两阶段统一契约

### 3.1 前半阶段：时间选择

输入：

- 原视频目录或单个视频；
- 数据集 manifest；
- 目标画幅信息；
- 时间模型、Prompt 和配置。

固定输出：

```text
temporal_handoff.jsonl     每条视频的时间段和原始帧范围
highlight_frames.jsonl     最终选择的原视频帧集合
temporal_report.json       模型调用、解析、回退和统计
frozen.json                代码、配置、Prompt、输入和模型指纹
```

### 3.2 显式交接适配器

后半阶段需要 `baseline.zip` 或等价空间输入时，只能由明确入口生成：

```text
build-spatial-input
```

适配器记录输入 handoff 哈希、生成规则、输出哈希和帧集合统计。它不能增加或删除高光帧，除非用户选择的是另一个已命名实验配置。

### 3.3 后半阶段：空间裁剪

输入：

- 已验证的时间交接或基础预测；
- 原视频和逐帧 PTS；
- 镜头缓存；
- 空间模型、Prompt 和配置。

固定输出：

```text
predictions_spatial.jsonl  逐帧 [x,y,w]
submission.zip             比赛提交结构
spatial_report.json        逐视频和逐 segment 摘要
validation.json            帧集合、边界、重复、NaN 和 ZIP 校验
frozen.json                本阶段完整指纹
```

### 3.4 可选择的运行方式

TUI 提供四种模式：

1. `Temporal only`：只跑时间阶段；
2. `Spatial only`：选择已有 handoff 或 baseline；
3. `Full pipeline`：前半完成并验证后自动进入后半；
4. `Resume run`：读取原运行目录，按 frozen 指纹续跑。

任何阶段失败时，后一阶段不得用不完整数据自动继续。

## 4. TUI 页面

### 4.1 首页

- 新建运行；
- 继续运行；
- 查看历史实验；
- 检查输入文件；
- 生成对比视频；
- 查看功能索引和文档。

### 4.2 新建运行向导

按顺序设置：

1. 运行模式；
2. 视频文件或目录；
3. dataset manifest/目标比例；
4. 前半阶段配置；
5. 前后阶段交接路径；
6. 后半阶段配置；
7. 中间工作目录；
8. 最终输出目录；
9. 预览和对比设置；
10. 资源配置；
11. 预检结果和完整执行计划。

路径输入同时支持键盘填写、最近使用路径和目录浏览。路径不存在、磁盘空间不足、输出覆盖或数据数量不匹配时，在启动前阻止运行。

### 4.3 实时运行页

显示：

- 当前阶段及总阶段；
- 已完成视频数/总数；
- 当前 video ID、segment、采样点和请求类型；
- 总进度与阶段进度；
- 已用时间和基于最近速度估算的剩余时间；
- GPU 利用率、显存、CPU、内存和磁盘占用；
- vLLM 正在运行和等待请求数；
- 最新日志；
- 成功、失败、跳过和复用缓存的数量。

界面刷新不能阻塞推理。运行状态来自结构化 `status.json` 和 `events.jsonl`，不依赖解析终端文本。

### 4.4 错误视频页

每个失败项记录：

```text
video_id
stage
segment/frame/request tag
错误类型和完整异常
最后成功断点
相关日志、模型原始回答和输入哈希
能否安全重试
```

支持查看全部失败、按阶段筛选、打开对应产物目录，以及在 frozen 指纹一致时只重试失败项。重试不得覆盖已完成记录；最终合并前重新做全量校验。

### 4.5 产物页

按“正式输出、中间证据、日志、预览、缓存”显示文件，附大小、SHA256 和生成阶段。用户能直接看到哪一个 ZIP 可以提交，哪一些只是调试文件。

## 5. 文件自动识别

新增只读扫描器，识别：

- 单个视频和视频目录；
- dataset manifest；
- temporal handoff；
- highlight frames；
- JSONL/ZIP 空间预测；
- v3 运行目录；
- 已完成、失败或可续跑的实验目录；
- 模型目录和 revision；
- 三路对比所需的基准/新结果配对。

扫描结果必须展示“为什么被识别成这种文件”和结构统计。存在多个可能解释时列出候选，不静默猜一个。

扫描器只读，不移动、重命名或覆盖文件。真正导入时生成一个引用 manifest，默认不复制大型视频。

## 6. 三路同步对比视频

默认布局：

```text
左：原画，并绘制基准/新结果框
中：基准版本实际裁剪画面
右：新实验实际裁剪画面
```

也支持把左侧改为原画无框、原画双框或时间选择状态。

### 6.1 时间和帧号规则

- 使用原视频 PTS 和原帧号对齐；
- 空间方案对比且高光帧集合相同时，逐帧一一对应；
- 两套时间选择不同时，使用两者高光时间轴并集，并明确显示 `baseline only`、`new only`、`both`；
- 不为了对齐而暗中改预测帧集合；
- 默认保持源时间速度，不做慢放或加速；
- 若输出编码要求恒定 FPS，必须在渲染配置中显示该 FPS，并在 manifest 中保存“输出帧 → 原始帧/PTS”映射。

### 6.2 画面与音频规则

- 三栏统一时间点、标题、video ID 和当前原帧号；
- 不把预览缩放误认为模型输入或比赛 bbox；
- 默认不混入音频，选择保留源音频时明确显示；
- 缺预测时显示占位和原因，不自动使用中心框伪装成结果；
- 输出 MP4、关键帧 JPG、对比 manifest 和校验报告；
- 生成后用 ffprobe/完整解码检查时长、帧数和损坏。

### 6.3 批量入口

支持：

- 指定 video ID；
- 失败视频；
- 变化最大的视频；
- 随机固定种子抽样；
- 全量生成网页索引；
- 将多段拼成一个 review reel。

已有 `preview_timeline.py`、`inspect_delivery_video.py` 和历史 preview 工具应先复用并抽取公共渲染模块，不再写第四套独立播放器。

## 7. 运行目录规范

每次运行使用一个独立目录：

```text
runs/<experiment_id>/
├── plan.json
├── frozen.json
├── status.json
├── events.jsonl
├── inputs.json
├── temporal/
├── handoff/
├── spatial/
├── errors/
│   └── failed_items.jsonl
├── logs/
├── previews/
├── comparisons/
└── final/
```

用户分别选择：

- `video_path`：原视频；
- `run_root`：本次运行和中间产物；
- `final_output`：最终 JSONL/ZIP；
- `cache_root`：可选的共享模型/只读缓存。

最终输出与中间目录不能混用。删除中间产物前，TUI 先列出仍被哪些实验引用。

## 8. 配置和资源策略

使用一份版本化 JSON 配置，至少包含：

```text
inputs
temporal
handoff
spatial
render
paths
resources
reproducibility
```

### 8.1 兼容资源模式

`compat` 完全使用当前基准的单序列、请求顺序和 OpenCV 线程设置。

### 8.2 优化资源模式

`optimized` 可以增加视频预读、减少重复解码、改线程或测试 vLLM 并发，但每项优化都必须：

1. 单独配置并记录；
2. 在固定样本上对比请求 payload、模型原始回答和最终 JSONL；
3. 显示是否“逐字节等价”或“新实验”；
4. 出现差异时自动归为新 pipeline/version，不能继续叫 compat。

TUI 不以 GPU 百分比决定是否悄悄修改算法参数。

## 10. 实施顺序

### P0：冻结本次基准（已完成）

- 保存完整 426 合并结果、提交 ZIP、报告和 SHA256；
- 校验源码、环境、模型、视频和外部输入；
- 为基准 Git 提交创建不可变 tag；
- 保留兼容启动和恢复说明。

当前状态：源码、环境、模型权重、外部输入与 426 条实际结果均已保存指纹，兼容入口、预检、合并和恢复说明已落库，并创建不可变 Git tag。空服务器实际恢复及 GPU 小样本复跑仍应在下一次申请 GPU 后执行一次。

验收：清空的新目录可以通过预检，并在小样本复跑中得到相同模型请求和结果。

### P1：统一运行契约

- 定义 `plan.json`、`status.json`、`events.jsonl` 和 `failed_items.jsonl`；
- 为时间、交接、空间、校验和渲染提供统一 CLI；
- 现有脚本包在 CLI 后面，算法不迁移两份。

验收：不用 TUI 也能用同一配置完整运行和续跑。

### P2：只读 TUI

- 扫描数据和历史运行；
- 显示状态、日志、资源、错误和产物；
- 不启动或修改任务。

验收：挂到当前基准运行目录时，显示内容与原始 JSON/日志一致。

### P3：TUI 启动和续跑

- 新建运行向导；
- 路径、配置和空间检查；
- 启动、停止、续跑和失败项重试；
- 完整命令和执行计划可复制。

验收：TUI 启动的 compat 小样本与命令行结果逐字节一致。

### P4：三路对比

- 抽取统一 PTS/帧读取和裁剪渲染模块；
- 实现空间同帧对比和时间差异对比；
- 输出视频、网页索引、帧映射和验证报告。

### P5：两阶段完整控制

- Full pipeline 状态机；
- 显式 handoff 适配器；
- 阶段间校验和断点；
- 实验台账自动登记。

验收：前半、后半、完整和续跑四种模式都能产出相同目录契约。

### P6：性能优化

- 每视频一次顺序解码；
- 下一视频预读；

验收：先保证 compat 结果不变，再比较耗时；有结果差异的方案单独登记。

## 11. 每阶段完成定义

一个功能只有同时满足以下条件才算完成：

- 有唯一入口；
- 有版本化配置；
- 有清楚的输入、输出和失败行为；
- 有可续跑状态；
- 有结构化校验；
- 不含隐藏帧率或帧号变换；
- README 和功能索引可找到；
- 与基准的结果关系已标明：完全一致、近似一致或新实验；
- 真实 GPU 小样本已验证，而不只是在本机通过单元测试。
