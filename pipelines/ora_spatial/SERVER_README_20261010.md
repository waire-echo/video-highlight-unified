## ORA 确实参与空间任务

`src/ora_stage.py` 中的处理顺序：

1. 对高光连续片段按原视频 TransNetV2 镜头边界分组，再拆成不超过 16 秒、240 个原始帧的小段。帧数上限控制 SAM 的主机内存峰值，不会丢弃原始保留帧。
2. 同一份 ORA 读取片段及已有事件描述，判断明确主体、多主体、整体景色或不确定；事件描述只是提示，要求以画面为准。该步骤采用 JSON Schema 约束输出，避免极短片段中模型反复续写说明文字。
3. ORA 对首尾及每 2 秒关键帧进行**单帧空间定位**：`build_spatial_grounding_prompt`，解析 `bbox_2d`。真实 GPU 试跑发现模型使用 0–1000 归一化坐标，已统一提示词和转换，映射回原视频尺寸；不再采用最初的像素坐标假设。
4. ORA 对视频进行**目标跟踪**：每秒一个框，使用 0–1000 归一化坐标。自定义提示词统一 key 0 为片段 0 秒、key 1 为第 1 秒，并根据原始 PTS 对齐原帧号。保留原始官方模板供参考，实际请求去掉了其与从零计时相冲突的示例。
5. 单帧框与临近跟踪框通过一致性检查后作为 SAM2.1 提示框。SAM 逐帧传播，检查面积、异常跳变、锚点一致性和距离最近复核的时间。
6. 没有可接受主体框或跟踪失效：非学习式显著性＋扣除全局平移的光流；证据弱则居中。
7. 在同一镜头和连续高光段内生成固定/平移虚拟相机轨迹、限制速度、保持原框宽并限制在画面内；严格校验后导出 JSONL/ZIP。

时序 ORA 结果直接复用；这里不会重新选择高光时间段，也不会调用第二个大语言模型。原始提示词及 ORA 回答保存在每个 `output/ora/<id>/<chunk>.json` 的 `audit` 中，可以检查真实的空间输出。

## 参数预算

- ORA 复用服务器原权重，逐分片 SHA256 与原实验 provenance 核对；实际张量数 **5,174,964,736**。
- SAM2.1 Hiera Large 约 0.224B；TransNetV2 约 0.0076B，均从实际 checkpoint 统计。
- 对继承的 YOLO 等旧空间模块额外保守预留 0.1B，不添加新检测器、ReID 或显著性大模型。
- 服务器实测的保守合计为 **5,507,029,690（约 5.507B）**，详见 `output/parameter_ledger.json`；超过 9B 或 ORA 权重不匹配立即退出。
- 多个任务调用同一权重只计一份模型。服务与 SAM 分阶段运行，显存占用与参数总量是两个不同约束。

## 验证与限制

无卡预检：

```bash
env/bin/python src/budget.py --ora-dir /root/rivermind-data/ora4b_v5_20261001/models/Video-ORA-4B --sam-checkpoint models/sam2.1_hiera_large.pt
env/bin/python scripts/preflight.py --video-dir /root/rivermind-data/ora4b_v5_20261001/videos
```

预检会核对全部视频 SHA256、输入指纹、测试用例，并在 CPU 加载真实 SAM2.1 权重。无卡阶段不能验证 ORA 的实际定位质量、CUDA 推理或显存峰值；这些由开卡后的试跑检查。

输出的 `.validation.json` 检查帧集合、框宽、坐标边界、ZIP 格式；`.report.json` 记录作用范围和改动数。缺失缓存、非有限坐标、权重变化、解码帧数不符会报错。

本机已生成 E1，并自动抽取位移较大及分散的视频做前后对比，见 `output/E1_comparison.jpg`。可视检查仍发现低置信度回中可能截掉主体的案例（如狗的头部），因此 E1 是用于测量的消融结果，不能当作已经确认更好的最终方案。需要进一步用 ORA 空间复核来处理主体类别错误和检测失效。

目前没有这三组的官方分数或真实构图标注，不能保证涨分；39.11 属于 R1，不能冒充本基线或 E1 的分数。固定/平移阈值、一致性阈值都是未用官方标签校准的初始工程参数。显著性可能受水印影响，多主体可能无法同时装入固定宽度框；应结合原视频可视化和官方评测决定保留哪组。

## 主体可见性复核：云端配对实验

新增 `src/ora_verify.py`，复用同一个 ORA 权重，不增加模型参数。先不提供事件描述或目标名称，让 ORA 描述候选框附近真实可见的内容，识别图标、文字和无法辨认的内容；再用完整原图核对目标身份、可见性和框的覆盖范围。只有原本通过空间/跟踪一致性且通过复核的框才允许成为 SAM 锚点。复核失败不等于景色视频，也不等于主体一定不存在。

SAM 输出校验增加了复核屏障：被拒绝或明确不可见的关键帧将支持区间分开，不能借用屏障另一侧的锚点继续认可跟踪结果。这是输出有效性控制，不代表已实测 SAM 的完整 GPU 传播。旧 ORA 缓存会因代码指纹变化而失效，必须通过主流程重新生成。

2026-10-08 在同一台 RTX 4090 上固定旧候选框进行配对复核：3 个视频、7 个片段，12 个旧锚点保留 7 个、拒绝 5 个。两个角落图标误框（0/405、0/424）和天空误框（269/0）被拒绝；完整可见的小狗框、3 个人物框、3 个可见太阳框保留。另拒绝一个没有覆盖所述整组主体的框，以及一个画面边缘模糊局部狗身框；后者说明此机制仍可能损失真实但难辨认的局部主体。

这只是针对已知错误的诊断实验，不能作为独立测试集准确率，也没有官方提分结论。局部主体仍需结合前后帧进一步验证，同模型两次复核仍可能共同出错。没有加入逐视频特调规则，没有改动时间帧或基线提交。全部 22 项自动测试在本机和云端通过；本次未运行 SAM GPU、全量 E2/E3 或官方提交，结束后 ORA 服务已关闭。
